## Fixes

### Capability Matching Now Follows the Server Exactly (`lumoauth_fastmcp.checks`)

`capability_covered()` and the `require_agent(...)` check compare agent capabilities in the form that the LumoAuth server stores. The 1.3.0 matcher differed from the server in two ways:

- It lower-cased every letter, but the server lower-cases ASCII letters only. An agent that held `ünits.read` therefore passed a check for `Ünits.Read`, although the server treats them as two different capabilities.
- It trimmed Unicode whitespace from both ends, but the server trims only space, tab, LF, CR, NUL and vertical tab.

Changes:

- `capability_covered(required, granted)` (`src/lumoauth_fastmcp/checks.py`) now calls `lumoauth.capabilities.any_capability_covers` from the Python SDK. The SDK's rules are tested against the same contract cases as the server's own matcher.
- The signature of `capability_covered()` is unchanged. Entries of `granted` that are not strings are now ignored instead of raising an error.
- Removed the private `_normalize_capability()` helper.

The other rules stay the same: `:` and `-` read as `.`, `*` covers every capability, and `users.*` covers `users.delete` but not `users` itself.

```python
from lumoauth_fastmcp import capability_covered, require_agent

capability_covered("tool:search_web", ["tool.search_web"])   # True
capability_covered("Ünits.Read", ["ünits.read"])             # False (True in 1.3.0)

@mcp.tool(auth=require_agent("billing.reminders"))
def send_reminder(invoice_id: str) -> str: ...
```

## Upgrade Notes

- **This release requires `lumoauth[verify]>=1.4.0`** (was `>=1.2.0`), because `capability_covered()` now uses `lumoauth.capabilities`. Upgrading `lumoauth-fastmcp` also upgrades the Python SDK to 1.4.0 or later. If your server code calls the SDK directly, read the upgrade notes of the Python SDK 1.4.0 release (`lumoauth`): for example, `AccessTokenClaims.has_capability()` now uses the same matching rules.
- **`require_agent(...)` can now refuse an agent that 1.3.0 admitted.** This happens only when the capability names differ in upper-case non-ASCII letters, or in leading or trailing whitespace that the server does not trim. The new answers match the server's.

## Tests

- Added `tests/test_capability_contract.py`. It runs the `covers` and `any_covers` cases in `sdk-contract/vectors/agent-capabilities.json` through `capability_covered()`. The contract repo checks the same cases against the server's own matcher. Set `LUMO_SDK_CONTRACT` to point the test at a contract checkout. Without one, the test is skipped.
- Added two non-ASCII cases to `test_capability_covered` in `tests/test_checks_and_policy.py`.

## Highlights

### 1. Capabilities in `<resource>:<action>` Form (`lumoauth_fastmcp.checks`)

An agent capability is one of the agent's OAuth scope values. LumoAuth now writes every capability as `<resource>:<action>`, such as `invoices:read`, with the wildcard `invoices:*`. `capability_covered()` and the `require_agent(...)` check use the matching rules of `lumoauth` 1.6.0, which follow the server:

- Capabilities compare in the server's canonical form: trimmed, ASCII letters in lower case, and `.` read as `:`.
- A `-` is now part of a name, not a separator. `users-delete` is a different capability from `users:delete`, and a held `users-*` is not a wildcard for `users:delete`.
- `*` covers every capability. `users:*` covers `users:delete` but not `users` itself.
- A `.` is still read as `:`. `require_agent("billing.refund")` still admits an agent that holds `billing:*`, and a held `users.*` still covers `users:delete`.
- An exact capability never covers a longer one: a held `web:search` does not cover `web:search_news`.
- `scope_covered()` and `require_scopes(...)` still compare token scopes exactly.

The doc comment of `capability_covered()` now describes these rules. The function and its signature did not change.

```python
from lumoauth_fastmcp import capability_covered, require_agent

capability_covered("users:delete", ["users:*"])            # True
capability_covered("Users.Delete", ["users:*"])            # True
capability_covered("users-delete", ["users:*"])            # False (True with lumoauth 1.5.0)
capability_covered("pull-requests:comment", ["pull-requests:*"])  # True

@mcp.tool(auth=require_agent("reminders:send"))
def send_reminder(invoice_id: str) -> str: ...
```

## Upgrade Notes

- **Upgrade `lumoauth` to 1.6.0 or later yourself.** `pip install -U lumoauth-fastmcp` does not upgrade `lumoauth` when 1.4.0 or 1.5.0 is already installed, because the package still allows those versions. A new install gets the latest `lumoauth`. Check the installed version with `pip show lumoauth`.
- **`require_agent(...)` can now refuse an agent that 1.3.1 admitted.** This happens when a name uses `-` where the agent's capability uses `:` or `.`. For example, `require_agent("users-delete")` no longer admits an agent that holds `users:*`. Write the capability as `<resource>:<action>`.
- **Write capabilities as `<resource>:<action>`.** LumoAuth refuses the dot form (`invoices.read`) when you register an agent's capability. Names in `require_agent(...)` may still use the dot form, because the check reads a `.` as `:`.
- **Read the Python SDK upgrade notes.** With `lumoauth` 1.6.0, `AccessTokenClaims.has_capability()` and `normalize_capability()` also change. `normalize_capability()` now returns `invoices:read` instead of `invoices.read`.
- No other dependency changes. The package still requires `fastmcp>=4.1,<5`.

## Documentation & Tests

- The `require_agent` example in `README.md` now uses `reminders:send`.
- The troubleshooting row for `Invalid Redirect URL` in `README.md` now says which ports LumoAuth accepts:
  - A public application accepts a changing port on `127.0.0.1`, `[::1]` and `http://localhost`.
  - A confidential application needs the exact port on `localhost`.
  - Register the URI without a port, such as `http://localhost/callback`, on a public application, or give the client a fixed callback port.
- Updated `test_capability_covered` and `test_require_agent_and_require_user` in `tests/test_checks_and_policy.py` for the new form. The new cases cover the `-` rule, the dot spelling, `pull-requests:*` and a longer name after an exact capability.
- `tests/test_capability_contract.py` runs the shared cases in `sdk-contract/vectors/agent-capabilities.json`, which are now in the `<resource>:<action>` form. Set `LUMO_SDK_CONTRACT` to point the test at a contract checkout. Without one, the test is skipped.
- With `lumoauth` 1.6.0, all 72 tests pass. With `lumoauth` 1.5.0, 4 of them fail: the contract test, two `-` cases in `test_capability_covered` and `test_require_agent_and_require_user`.
- Added the release notes for v1.3.1 (`release-notes/v1.3.1.md`).
